# 部位轮换规则

> 决定**今日训练主题**(推/拉/腿/上肢/下肢/全身/有氧)的算法。
> 输入:飞书 Base 训练日表过去 7 天记录。
> 输出:今日主题 + 候选主题列表。

---

## 1. 部位分类

| 类别 | 主练肌群 | 典型动作 |
|---|---|---|
| **推** | 胸/肩/三头 | 卧推、推胸、肩推、双杠臂屈伸 |
| **拉** | 背/二头 | 高位下拉、坐姿划船、引体向上、二头弯举 |
| **腿** | 股四/腘绳/臀/小腿 | 倒蹬、深蹲、腿屈伸、RDL、提踵 |
| **核心** | 腹/竖脊 | 卷腹、罗马椅(plank/俯身挺身) |
| **上肢** | 推+拉 | 上肢综合 |
| **下肢** | 腿+核心 | 下肢综合 |
| **全身** | 推+拉+腿 | 全身综合 |
| **有氧** | 心肺 | 跑步、快走、单车、椭圆机 |

## 2. 轮换基础规则

### 恢复间隔

| | 教科书值 | **本 skill 实际采用** |
|---|---|---|
| 大肌群(胸/背/股四/腘绳/臀) | ≥ 48h | **≥ 24h** |
| 小肌群(肩/臂/小腿/核心) | ≥ 24h | ≥ 24h |

48h 是理想值,与用户的实际节奏(早/午/晚分时练,倾向每日练)不符,详见第 4 节。
**实现只有一个阈值**:`fitness_lib.MIN_REST_DAYS = 1`。

> 此前本文 §2 写 48h、§3 步骤 3 写 `days_ago ≥ 2`、第 4 节写降到 24h、代码写 `days >= 1`,
> 四处不一致。现在统一到上面这一个常量,改它一处即可。

### 经典 3 分(7 日分布)

| 周几 | 主题 | 备注 |
|---|---|---|
| 周一 | 推 | 周末休息后第一练 |
| 周二 | 拉 | 推 +24h |
| 周三 | 腿 | 拉 +24h |
| 周四 | 推 | 推 +72h |
| 周五 | 拉 | |
| 周六 | 腿 | |
| 周日 | 主动恢复 | 快走 30-60 min Zone 2 |

## 3. 算法(从 Base 训练日表读 7 天 → 决定今日)

### 输入
- `训练日表` 过去 7 天记录(按日期 desc 排序)
- 今日日期 `today`

### 输出
- `主题`(SingleSelect)
- `候选列表`(前 3 个推荐)

### 步骤

1. **取过去 7 天主题序列**(按日期 desc):
   ```
   [
     {date: '2026-07-25', topic: '腿'},
     {date: '2026-07-23', topic: '推'},
     {date: '2026-07-21', topic: '腿'},
     ...
   ]
   ```

2. **计算每个主题距今天数**:
   ```python
   for topic in [推, 拉, 腿]:
       last_date = max(r.date for r in records if r.topic == topic)
       days_ago = (today - last_date).days
   ```

3. **筛选可练主题**(`days_ago ≥ MIN_REST_DAYS`,即 ≥ 1 天)

4. **排序:窗口内没练过的排最前,其余按距今天数降序**
   - 例:窗口内 leg=1 天、pull=3 天、push 无记录 → 选 **push**
   - 例:leg=1 天、pull=3 天、push=2 天 → 选 **pull**(3 天最久)

   ⚠️ **「没练过」必须排最前,这是本算法最容易写反的地方。**
   旧实现用 `if last:` 过滤,7 天内没有记录的主题**直接被排除在候选之外** ——
   于是最久没练、最该练的那个部位反而永远选不上,和「选距今最久」正好相反。

5. **fallback:所有大肌群距今 < 1 天**
   - 推核心 / 主动恢复(快走 30-60 min)
   - 不轻易纯休息

## 4. 用户特化(2026-07-25 现状)

### 历史主题分布(MEMORY 抽取)
- 7/8:腿
- 7/14:腿(同日备注含跑步 → 主题仍选「腿」)
- 7/15:推(41kg 推胸 PR)
- 7/17:拉(Pull Day 6317 kg)
- 7/18:腿(踝友好版 + 提踵首练 + 临时加推胸)
- 7/21、7/23、7/25:base 有记录但 memory 缺细节

### 决策偏好(用户 2026-07 反馈)
- **倾向每日练**:7/25 起 base 显示连续 3 日有训练日记录
- **强度宁轻勿重**:踝疼 → 立刻降重,主题不取消
- **大肌群间隔实际 < 48h** 但 ≥ 24h(因为早晨 / 午后 / 晚上分时练)

### 算法调整
- **大肌群间隔硬阈值降到 ≥ 24h**(原 48h 偏理想化,与用户实际节奏不符)
- **用户明确说"今日练 X" → 直接采用,跳过算法**(用户 override 优先)

## 5. 备选主题:有氧 / 主动恢复

当**所有大肌群距今 < 24h** 时:

| 选项 | 适用场景 | 时长 |
|---|---|---|
| 主动恢复(快走) | 全身疲劳但关节无碍 | 30-60 min Zone 2 |
| 核心 / 灵活性 | 无大肌群疲劳 | 15-20 min |
| 纯休息 | 伤病 / 极度疲劳 | — |

用户偏好:**优先核心或主动恢复**,不轻易纯休息(2026-07-18 验证:腿日之后当晚 30 min 散步)。

## 6. 异常处理

### 局部疲劳未恢复(单一肌群)
- 例:7/18 leg 后,7/19 推 → 推日避开股四激活(不做深蹲、弓步)
- 选择:**卧推(纯胸)/ 哑铃推举(肩)/ 推胸器(零踝压)**

### 伤病 / 疼痛
- 例:7/18 右脚踝疼 → leg 日换踝友好版本(坐姿/俯卧优先)
- 详见 `exercise-substitutions.md`

### 设备被占
- 例:7/18 腿屈伸机被占 → 临时加推胸(等机器期间)
- 决策:动作库选最接近替代,**主题不切换**(leg 日就 leg)

## 7. 快速决策样例

### 例:今日 7/22(周二)· 三个主题都练过
- 过去 7 天:`leg (7/21)`、`pull (7/17)`、`push (7/15)`
- leg 距今 1 天 ✅ 可练｜pull 距今 5 天 ✅｜push 距今 7 天 ✅
- **算法输出**:选 **push**(7 天,候选中最久)
- **用户 override**:用户 7/22 想练腿(踝好了)→ **采用腿**
- **最终**:腿日,踝友好版可解除 → 倒蹬高脚位 + RDL + 腿屈伸 + 腿弯举 + 提踵(进阶)

### 例:今日 7/19(周六)· 只有一个主题有记录
- 过去 7 天:`leg (7/18)`,push / pull **窗口内无记录**
- leg 距今 1 天 ✅ 可练
- **算法输出**:选 **push**(窗口内未练过 → 优先级高于任何练过的)

  📌 这个例子正是旧实现踩的坑:`if last:` 会把没有记录的 push / pull 直接跳过,
  只在 leg 一个候选里挑,最后输出「昨天刚练过的 leg」或「主动恢复」。
  没练过的部位反而排不上号。

### 例:今日 · 三个主题今天都练过
- 过去 7 天:`push / pull / leg` 全是今天
- 三个 days_ago 都 = 0 < 1 → 无可练候选
- **算法输出**:主动恢复(候选:核心 / 有氧)

## 8. 实现

**实现在 `scripts/fitness_lib.py`,不在本文档里。**

from datetime import date
from fitness_lib import decide_today_topic

decide_today_topic(
    date(2026, 8, 3),
    [{"date": date(2026, 8, 2), "topic": "腿"},
     {"date": date(2026, 7, 31), "topic": "拉"}],
)
# → {'topic': '推', 'candidates': ['推', '拉'], 'reason': '窗口内未练过,优先安排'}

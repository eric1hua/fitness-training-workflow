# 飞书 Base 录入规范

> 这份文档是**唯一真源**。任何 agent 往这个 Base 写数据前必须遵守。
> 代码里的校验（`scripts/base_writer.py` 的 `validate_record()`）和审计
> （`scripts/base_audit.py`）都按本文实现，改规则先改这里。

## 为什么需要它

同一个 Base 有**多个独立实现**在写：本仓库的 `fitness-training-workflow`，以及另一台
机器上的 `fitness-coach`。两边的记录 ID 约定恰好一致，所以一直没打架——但没有
共同契约，已经写出过这些：`容量kg` 整列为空、`开始` 写成 12 小时制、`总次数` 缺失、
`配速` 写成 `11:41 /km`、组记录没挂到当天训练日上。

规范的作用是让这些**写不进去**，而不是写进去以后靠人翻表发现。

## 适用范围

所有向本 Base 写入的 agent，无一例外。当前已知：

| `录入agent` 取值 | 是谁 |
|---|---|
| `kepano@imac` | iMac 上 openclaw 的 kepano 子 agent（收工整理 / 计划生成）|
| `elon@imac` | iMac 上 openclaw 的主 agent |
| `rock@macmini` | Mac mini 上的 Rock（`fitness-coach`）|

新增部署自行登记，格式 `<agent 名小写>@<主机短名>`，不带空格。

## 通用规则（四张表都适用）

### `录入agent` — 必填

每条记录都要署名。缺了就无法追溯是哪个实现写的，出问题只能靠日期猜。

取值见上表。本仓库从 `config.json` 的 `agent_id` 读取，也可用环境变量
`FITNESS_AGENT_ID` 覆盖。

### `记录ID` — 必填，格式固定

| 表 | 格式 | 例 |
|---|---|---|
| 训练日 | `session-YYYY-MM-DD` | `session-2026-08-02` |
| 训练组 | `set-YYYY-MM-DD-NNN` | `set-2026-08-02-004` |
| 有氧 | `cardio-YYYY-MM-DD-NNN` | `cardio-2026-08-02-001` |
| 体测 | `body-YYYY-MM-DD-NNN` | `body-2026-08-02-001` |

`NNN` 是**当日全局流水号**，从 `001` 起，三位补零。它跟训练组的 `组序` 不是一回事——
`组序` 是该动作内部的第几组。命名规则的完整说明见 `record-id-conventions.md`。

同日二次写入必须先查库续号，不能从 `001` 重来。

### `日期` — 必填

`YYYY-MM-DD`。所有表都有这个字段，其他字段不重复承载日期。

### `训练者` — 已废弃，不要再写

每个训练者现在各自拥有一张独立的多维表格，这个字段没有区分作用了。

历史值保留不动。已经在写的实现不算错，但不必再维护。

## 训练日 表

| 字段 | 必填 | 格式 / 取值 |
|---|---|---|
| 日期 | ✅ | `YYYY-MM-DD` |
| 主题 | ✅ | 推 / 拉 / 腿 / 上肢 / 下肢 / 全身 / 有氧。指**主体无氧主题** |
| 开始 | ✅ | **`HH:MM`，24 小时制**。不含日期 |
| 结束 | ✅ | 同上 |
| 时长min | ✅ | 整数。**只算无氧**，有氧时长单独进有氧表 |
| 总组数 | ✅ | 当日训练组条数 |
| 总次数 | ✅ | 当日训练组 `次数` 之和 |
| 总容量kg | ✅ | 当日训练组 `容量kg` 之和 |
| 组数明细 | ✅ | Link → 训练组，指向当日**全部**训练组记录 |
| 录入agent | ✅ | 见通用规则 |
| 记录ID | ✅ | `session-YYYY-MM-DD` |
| 备注 | — | 自由文本 |

### 时间格式

写 `11:30`，不写 `上午11:30`、`11:30 AM`、`9:5`、`2026-08-02 11:30:00`。

日期已经由 `日期` 字段承载，时间字段只管时间。

> 2026-08-04 那条就是从这里漏进去的。

### `总次数` 不能缺

它等于当日训练组 `次数` 的和，是可以算出来的，没有"没记到"这一说。缺了就是漏写。

> 2026-08-02 那条缺了这个字段。

### `组数明细` 双向链接

写完当日全部训练组之后，必须回填这个 link 字段，把当天所有组记录挂上去。

漏了的话，训练日和它的组记录在 Base 里是断开的——展开训练日看不到明细，
按训练日聚合的仪表盘也会算空。

CellValue 形状是 `[{"id": "recXXX"}, ...]`，不是裸字符串数组。

## 训练组 表

| 字段 | 必填 | 格式 / 取值 |
|---|---|---|
| 日期 | ✅ | `YYYY-MM-DD` |
| 训练日 | ✅ | Link → 训练日，指向当日训练日记录 |
| 动作 | ✅ | 中文动作名，以 `exercise-substitutions.md` 的写法为准 |
| 肌群 | ✅ | 股四 / 腘绳 / 臀 / 小腿 / 胸 / 背 / 肩 / 臂 / 核心 |
| 类别 | ✅ | 推 / 拉 / 腿 / 核心 / 肩 / 臂 |
| 组类型 | ✅ | 热身 / 正式 / 顶组 / 收尾 |
| 组序 | ✅ | 该动作内部的第几组，从 1 起 |
| 重量kg | ✅ | 数字，小数照写（`37.5`、`82.5`）|
| 次数 | ✅ | 整数 |
| RPE | — | 0–10。热身组可留空 |
| 容量kg | ✅ | `重量kg × 次数`，保留 1 位小数 |
| 录入agent | ✅ | 见通用规则 |
| 记录ID | ✅ | `set-YYYY-MM-DD-NNN` |
| 备注 | — | 自由文本 |

### `容量kg` 要自己算并写入

这个字段**不是公式字段**，Base 不会替你算。不写就是整列为空。

值必须等于 `重量kg × 次数`，校验会对这个等式做一致性检查。

> 本仓库此前把它当公式字段主动过滤掉了（`base-schema.md` 记载有误），
> 导致这台机器写的组记录这一栏全空。

### `训练日` 链接

每条组记录都要挂到当天的训练日记录上。形状 `[{"id": "recXXX"}]`。

这是双向链接的另一半，跟训练日的 `组数明细` 配套。只挂一边等于没挂。

### `组序` vs `记录ID` 里的 `NNN`

- `组序`：这个**动作**的第几组。倒蹬做 3 组就是 1、2、3；换成腿屈伸重新从 1 开始
- `NNN`：当日**全局**第几条记录，一直往上加

两者用途不同，别混。

## 有氧 表

| 字段 | 必填 | 格式 / 取值 |
|---|---|---|
| 日期 | ✅ | `YYYY-MM-DD` |
| 方式 | ✅ | 跑步 / 单车 / 椭圆机 / 游泳 / 步行 |
| 距离km | ✅ | 数字 |
| 时长min | ✅ | 整数。有氧时长单算，不进训练日的 `时长min` |
| 配速 | ✅ | **`MM:SS`，不带单位** |
| 平均心率 | — | bpm |
| 卡路里 | — | kcal |
| 备注 | 条件必填 | 见下 |
| 录入agent | ✅ | 见通用规则 |
| 记录ID | ✅ | `cardio-YYYY-MM-DD-NNN` |

### `配速` 不带单位

写 `11:41`，不写 `11:41 /km`、`11:41/km`、`11分41秒`。

单位是字段语义的一部分（min/km），不需要在每条值里重复。带了单位这一列就没法做
数值比较和图表。

> 2026-07-29 和 2026-08-04 两条椭圆机记录就是这么写的。

### `备注` 要记器械参数

同样的距离和时长，坡度和阻力不同，训练强度差很远。不记的话这条数据后面无法解读。

| 方式 | 备注必须包含 |
|---|---|
| 跑步 | 坡度，写法 `坡度 3%` |
| 椭圆机 | 阻力，写法 `阻力 8` |
| 其他 | 无强制要求 |

可以和其他备注内容并存，用 `｜` 分隔：`坡度 3%｜跑步机 2 号`。

## 体测 表

当前只有 `fitness-coach` 写这张表，本仓库没有对应流程。

| 字段 | 必填 | 格式 |
|---|---|---|
| 日期 | ✅ | `YYYY-MM-DD` |
| 体重kg | ✅ | 数字 |
| BMI / 体脂率 / 体脂kg / 去脂体重kg / 骨骼肌kg | — | 数字 |
| 基础代谢 / 代谢年龄 / 内脏脂肪等级 / 腰臀比 / 体成分评分 | — | 数字 |
| 录入agent | ✅ | 见通用规则 |
| 记录ID | ✅ | `body-YYYY-MM-DD-NNN` |
| 备注 | — | 建议记测量设备与时段（如 `Visbody｜晨起空腹`）|

体测数据受测量条件影响很大，同一台设备、同一时段的数据才有可比性——所以备注里
记设备和时段虽然不强制，但缺了会让趋势对比失去意义。

## 怎么保证被遵守

**写入前**：`scripts/base_writer.py` 的 `validate_record()` 按本文校验，违规
直接退出不写。另一个实现自行实现同等校验。

**写入后**：`scripts/base_audit.py` 扫全表报告违规。**这个只需要在任意一台机器上跑，
就能覆盖所有实现的写入**——因为它查的是 Base，不是本地缓存。

```bash
python3 scripts/base_audit.py                  # 报告
python3 scripts/base_audit.py --fix --dry-run  # 看要修什么
python3 scripts/base_audit.py --fix            # 修可确定项
```

`--fix` 只动有唯一正确答案的三类：配速去单位、时间归一为 `HH:MM`、`总次数` 按当日
训练组求和回填。缺链接、缺 `录入agent`、`容量kg` 为空只报告不修——那些该由写入方补。
